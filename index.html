Case Study · LLM Serving & Evaluation

HR AI Evaluation Lab

An automated system that reads resumes in Arabic and English, turns them into structured candidate profiles, and scores each one against a job description, showing matched and missing skills.

01 / The problem

Screening resumes is slow, and bilingual.

HR teams receive resumes in different formats and languages. Reading each one and comparing it to a job description by hand takes time and is hard to keep consistent.

Goal

Extract a reliable structured profile from every resume, in Arabic or English, and rank candidates against a job description with clear evidence of which skills match and which are missing.

The question behind it

Is a self-hosted open model good enough, and affordable enough, compared with an API-based model for this kind of extraction and matching work?

02 / How it works

From resume to ranked candidate.

Read

03

04

03 / Stack & serving

Self-hosted, containerized, observable.

The model runs on our own infrastructure rather than a third-party API, which made serving and monitoring part of the project.

Application and model

  • FastAPI service exposing the extraction and matching endpoints.
  • Qwen2.5-14B served with vLLM on a single GPU.
  • Prompts kept as versioned files so they can be compared.
  • Structured JSON output from the LLM, validated before use.

Deployment and operations

  • Docker images for the services.
  • Kubernetes manifests for deployment.
  • Monitoring configuration for tracking the running system.
  • A dedicated evaluation folder for the benchmark runs.

04 / Evaluation

Quality and speed, measured separately.

The lab treats the model as something to be measured, not just called.

Extraction quality

  • F1 score on extracted fields.
  • Hallucination checks on what the model produced.
  • Results compared across Arabic and English resumes.

Serving performance

  • Time to first token.
  • Throughput under load.
  • End-to-end latency.
  • Self-hosted versus API-based models on quality and cost.

05 / What we learned

Lessons from running the model ourselves.

Serving

How to host and serve an LLM on a single GPU with vLLM, and how to read serving metrics to judge whether a setup is practical.

Reliability

How to get dependable structured JSON out of an LLM, and how to measure extraction quality rather than judge it by eye.
