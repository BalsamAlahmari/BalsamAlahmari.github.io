01 / The problem

Specialized knowledge is buried in long documents.

Logistics information is distributed across reports, manuals, regulations, and supply-chain references. Keyword search can miss semantically related information, while an ungrounded language model can produce unsupported answers.

Goal

Create an assistant that understands natural-language logistics questions, retrieves relevant passages, and answers from the retrieved evidence.

Knowledge base

Trusted academic, industry, and government PDFs covering transportation, warehousing, inventory, procurement, supply-chain optimization, and logistics technology.

02 / My contribution

Implemented the RAG system.

I built the core flow from document ingestion and chunking through semantic retrieval and grounded response generation.

Retrieval pipeline

  • Loaded source PDFs with LangChain.
  • Split text into 800-character chunks with 80-character overlap.
  • Embedded chunks with all-MiniLM-L6-v2.
  • Stored and searched vectors in ChromaDB.

Generation pipeline

  • Retrieved top-k chunks by semantic similarity.
  • Constructed a context-restricted prompt.
  • Generated answers with Llama 3.1 8B through Groq.
  • Returned supporting chunks and source metadata.

03 / Architecture

Retrieval before generation.

01

Ingest

02

03

Retrieve

04

Generate

Answer from the retrieved context and expose the sources.

05 / Interface

Evidence stays visible.

The Streamlit interface provides chat history, top-k control, retrieved chunks, and source pages so users can inspect the context behind each answer.

06 / Outcome

A transparent prototype for logistics knowledge access.

The final system combines semantic retrieval, grounded generation, evidence display, and quantitative RAG evaluation.
